# RC14.12：个人空间与全部文件共用文件管理器

## 更新目标

`/personal` 以前采用独立的 `renderSpaces(..., true)` 简化排版：左侧列出空间名称，右侧在当前空间中以单列逐级浏览目录。现改为和 `/files` **直接共用** `public/js/modules/file-manager.js` 的浏览器模板，而不是建立第二套样式或复制文件操作代码。

### 现在的界面

- **桌面端**：左侧为可展开/折叠的多级文件夹树（懒加载子目录，支持超过 100 项时加载更多），右侧为选中目录下的文件夹与文件。
- **右侧工具栏**：搜索、文件类型筛选、排序、列表/网格切换、刷新；文件夹和文件均从现有 ACL 接口实时获取。
- **文件操作**：点击或双击目录打开，面包屑返回，预览、下载、收藏、分享、上传、批量选择、移动、复制、重命名、删除、历史版本与文本编辑（具体操作按文件类型和后端权限开放）。
- **目录权限**：拥有对应空间管理权限的用户可从目录操作区设置角色覆盖，延续旧版 `/personal` 的能力。
- **移动端**：沿用 `/files` 的响应式布局，目录树位于上方、文件区在下方；操作按钮与桌面端保持一致。

### 路由与权限

| 地址 | 前端页面 | 空间范围 |
| --- | --- | --- |
| `/files` | `renderFileManager(host, 'files')` | 当前登录用户有权限访问的个人和团队空间 |
| `/personal` | `renderFileManager(host, 'personal')` | 仅 `type='personal'` 的可访问空间 |
| `/spaces` | `renderSpaces(host, false)` | 团队空间及其成员/角色管理，保留原界面 |

前端先过滤 `/api/v1/spaces` 的个人空间，后续内容依然通过 `/api/v1/spaces/{spaceId}/contents`、`/api/v1/spaces/{spaceId}/folders` 等原有接口获取；**Worker 的实际 ACL 检查不变**。没有任何权限扩大或私有文件开放。

两页上次访问目录分别存储于 `sessionStorage` 的 `cd-last-folder`（全部文件）和 `cd-last-personal-folder`（个人空间），避免相互污染；会校验恢复的文件夹是否属于当前空间且仍可访问。`/files` 的原有旧 `parentId` 记录仍可恢复。

### 修改的主要文件

- `public/js/main.js`：`/personal` 改为使用同一个 `renderFileManager`。
- `public/js/modules/file-manager.js`：新增个人空间过滤、独立的目录位置缓存键、个人空间标题和权限操作；点击目录时与左侧树保持同步。
- `public/js/components/folder-tree.js`：支持从深层目录恢复时逐页加载祖先目录，解决同级文件夹超过 100 个时树无法高亮的问题。
- `public/js/components/folder-permissions.js`：提供权限覆盖弹窗，延续原个人空间的目录权限设置能力。
- `tests/personal-explorer-shared.test.js`：真实 Worker + SQLite 模拟响应的专项回归测试。

没有新增 D1 迁移，不需要修改 R2 桶或 Microsoft Secrets。

## 升级

基于 **CloudDrive RC14.12 个人空间文件显示修复版**：

1. 备份当前代码（特别是自定义过的 `wrangler.jsonc`）。
2. 将补丁内的文件按原相对路径覆盖到项目目录；**不要删除或重建 D1/R2**。
3. 执行 `npm run build` 和 `npm run deploy`。
4. 清理旧的前端资源缓存或强制刷新页面。

## 浏览器验收清单

1. 用普通账号登录 `/personal`，确认只出现自己的个人空间；即使另有团队空间也不显示在个人空间下拉中。
2. 左侧逐级展开目录树，并通过树节点切换右侧内容；右侧双击文件夹可同步树状态和面包屑。
3. 对比 `/files` 中同一空间的相同目录，确认文件夹及已完成上传的文件均可见。
4. 检查只含文件、无子文件夹的目录不被判为空；超过 50 项可以翻页。
5. 测试列表/网格、搜索、筛选、排序、预览、下载、上传、分享和目录权限功能。
6. 在 `/personal` 打开深层目录后刷新，确认能恢复当前目录；再访问 `/files`，确认其原来选中的目录不受影响。
7. 在手机或窄窗口中验证目录树上下布局及文件操作。

> 注意：前端只能显示后端确认 `ready` 且有权限读取的文件；回收站、上传中和未授权的文件仍不会出现。本次未直接部署到生产网站。
