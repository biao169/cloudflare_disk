# 系统管理与安全功能

## 管理入口

- `/settings` 提供容量与核对、清理维护、异常日志、备份与恢复、站点设置、OneDrive 配置等页签。
- `/users` 管理成员和额度，`/spaces` 管理团队及权限，`/trash` 恢复或清理已删除文件。
- `/api/v1/health/ready` 检查 D1/R2/ASSETS 绑定和基础 schema 是否完成，但不能代替真实文件上传下载测试。

## 配额与维护

- 用户与空间配额在 D1 中管理；上传过程中有容量预留，失败清理与后台对账用于减少账本偏差。
- Cron 默认每六小时触发一次，执行分批的会话、分享、OneDrive 授权状态、同步健康及过期记录维护。
- 一部分第三方 API 在 429 时要求尊重 `Retry-After`。不要通过无限重试或高并发请求绕过微软限制。
- 后台记录脱敏异常和维护状态，不记录 Microsoft 访问令牌、明文密码和临时下载 URL。

## 安全边界

- 登录密码 6–128 个 Unicode 字符，PBKDF2-SHA256 哈希。分享访问密码为独立规则。
- `BOOTSTRAP_TOKEN` 只用于首次创建管理员；`SHARE_LINK_KEY` 用于安全恢复新分享链接；`MS_TOKEN_KEY` 用于 Microsoft Token 加密。三者都应单独随机生成并长期保存。
- R2 私有桶不设置公开域名。OneDrive 管理员授权不自动授予游客下载未发布文件的权限。
- 所有写接口应检查会话、Origin/CSRF 及实际对象 ACL；浏览器隐藏按钮不代替后端权限验证。
- 数据库结构调整与清库属于不同操作。当前单文件 `migrations/0001_initial.sql` 只负责全新数据库初始化；完整旧库按历史记录直接沿用。旧库不完整时部署脚本拒绝覆盖，必须先补齐旧版迁移或显式切换新数据库。

## 备份与恢复

- `npm run db:backup:remote` 导出 D1 数据库，**不含 R2 文件**；R2 需要单独下载或使用已授权的备份工具。
- 生产升级前备份 D1 和私有/公开 R2 桶，保留原数据库 ID、桶名、Microsoft Secrets 和 Worker 名称。
- 不要在现有数据上执行未经审核的 `DROP TABLE` / `DELETE FROM`，也不要直接从代码包重建原数据库并期待历史分享继续可用。
- 如决定放弃历史数据，优先在 Cloudflare 创建一个全新的 D1，并修改 `wrangler.jsonc` 中目标 `database_name`；不要复用旧数据库名称以免错误升级。新库会重新创建管理员，旧文件的 D1 引用、分享链接、配额和 OAuth 状态不会自动迁入。
