# CloudDrive RC13.3 — 文件夹合并、镜像替换和持久化进度

> 从 RC13.2 升级：**增量数据库迁移 `0021_rc13_3_folder_sync.sql`**。不删除或重建用户、目录、文件、版本、公开副本和私密分享记录；不更换任何 R2 对象 Key、Worker 名称、D1 ID 或运行时 Secret。

## 网页使用方法

1. 登录 `/files`，进入要上传文件夹的**目标父目录**（例如“团队资料”）。
2. 点击 **“📁 合并/镜像更新文件夹”**，在 Chrome/Edge 选择本地文件夹；或直接拖拽本地文件夹。浏览器上传清单保留相对目录结构。
3. 看到当前文件夹的差异预览：**新增文件 / 替换文件 / 创建目录 / 删除旧文件 / 删除旧目录**。
4. 选择模式：
   - **合并更新（默认）**：复用同名文件夹；同路径同名文件更新内容、保留 `files.id` 和已有私密链接；新文件新增；本地没有的旧文件保留。
   - **镜像替换**：同上，但当所有新上传项目已在 D1 中确认成功，才**逐项移入回收站**本地清单里缺少的旧项目。需勾选明确确认。镜像不会先物理删除 R2 对象。
   - **保留两个文件夹**：创建 `文件夹 (1)` 等新根目录，原目录与分享完全不变。
5. 页面显示每个项目的完成/失败数和当前文件的进度。**暂停/关闭页面不会清空已完成项**。重新选择相同的本地文件夹，若清单未变化可接续同一个任务，旧数据不会被提前清理。

**既有分享仍有效：** “替换”延用 RC13.1 的新 R2 对象 + D1 修订号 CAS；文件 ID 不变，`/s/*` 和 `/t/*` 指向新文件。RC13.2 的 `/r/*` 会按已有策略同步新版公开副本，直达 CDN 旧别名仍受缓存规则约束。文件夹 ID 不变的情况下，原文件夹分享保留；镜像模式主动移入回收站的文件/文件夹，其独立分享会撤销。

## 安全、并发与失败恢复

- 浏览器传入**相对路径清单**；服务端重新计算同名冲突、整个文件夹差异、文件身份、权限及并发修订号。**不会信任浏览器声称的“已上传成功”**，每项完成时要检查 D1 中的真实文件/目录、文件大小、类型、版本号和权限。
- `POST /plan` **不修改文件/数据库**；`POST /jobs` 重新计算计划，比较 `plan_hash`，拒绝被其他用户修改过的旧计划。镜像必须额外 `confirm_mirror: true`。
- 每个上传仍使用 RC13.1 原有普通上传或 Multipart 接口，沿用写权限、存储配额预留、版本冲突和 RC13.2 公开副本同步机制。新版本发布失败时，现有版本/原公开版本仍可用。
- 镜像删除前再检查**目录快照**。并发新增、移动、重命名、修改现有文件会返回 `MIRROR_STALE`，旧项目不会被静默删除，需要重新预览。开始删除后每个 HTTP 请求只清理 1 项，独立复核目标 ID/路径/版本及实时 ACL；失败保留任务进度。重试时识别已在回收站的已提交项目，防止重复删除。
- “停止后续任务”只是暂停新的文件上传/删除请求，并不回滚已经成功上传的文件；任务超时后自动停止，过期日志后续清理。
- `folder_sync_jobs` 的历史目录 ID 不设外键，避免保留的运维日志阻止回收站永久删除旧目录。
- **重要边界：整个文件夹更新不是跨 R2/D1 的一次原子事务。** 其中已成功替换的文件立即可见；某项失败时保留先前成功的变更，**镜像未处理的旧项目不删除**。其他人可以在进行中的同步中继续读旧版/当前版文件。

## 免费账户边界

为控制单次 Worker CPU、D1 读取行数和 SQLite 绑定参数，单个文件夹任务默认限制 **150 个上传文件、100 个显式本地目录、最多 280 个已有文件/目录、12 层目录**。单项被删除的旧目录子树最多 200 项，与现有回收站保护一致。超限会给出明确提示，建议逐级拆分子文件夹同步。目录树包含更深或无法完整枚举的项时，镜像模式拒绝执行，避免误删。

上传大小继续受原项目每文件最大 8 GiB、R2 免费容量和单次对象公开副本限制约束；版本/公开副本仍占用容量。**不新增 Worker/R2/D1 资源、不需要新 Secret、不会免费无限存储。**

### 已知浏览器差异

- Chrome/Edge 文件夹选择可保留包含文件的相对路径，但浏览器的 `webkitdirectory` 文件列表一般**不包含空目录**。拖拽目录时支持额外记录空目录。
- 只在同一个目标空间的根/子目录中完成单个文件夹更新，不自动跨空间镜像迁移。
- 当任务中断且需要重新选择本地文件时，浏览器无法永久保留读取本地文件的权限；用户需再次选择同一文件夹。状态保存在 D1，前端只保存任务 ID 与本地文件清单指纹。
- 下载已开始或被第三方缓存的内容不会被强制更新；固定 `/r/*` 在新请求时解析当前已发布版本。

## API（需要网盘登录和原有 CSRF 防护）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/folder-sync/plan` | 只读差异预览，返回 `plan_hash`、counts、逐项计划 |
| POST | `/api/v1/folder-sync/jobs` | 提交并重新校验同一计划；镜像必须 `confirm_mirror: true` |
| GET | `/api/v1/folder-sync/jobs/{jobId}` | 读取持久任务进度，包含每项 `status`、`target_id` 和结果 ID |
| POST | `/api/v1/folder-sync/jobs/{jobId}/items/{itemId}/ack` | 检查文件/目录真实写入，记录不可重复的完成标记 |
| POST | `/api/v1/folder-sync/jobs/{jobId}/finish` | 全部上传确认后结束合并，或按次执行一个安全镜像删除动作 |
| POST | `/api/v1/folder-sync/jobs/{jobId}/cancel` | 停止尚未开始的操作，不回滚已有成功内容 |

示例规划请求：

```json
{
  "space_id": "<your-space-id>",
  "parent_folder_id": null,
  "root_name": "项目资料",
  "mode": "mirror",
  "files": [
    {"path": "设计说明.pdf", "size_bytes": 14052, "mime_type": "application/pdf"},
    {"path": "图像/front.jpg", "size_bytes": 8062, "mime_type": "image/jpeg"}
  ],
  "directories": ["图像"]
}
```

需要从 `POST /plan` 取 `plan_hash`，将相同请求体和 `plan_hash` 及 `confirm_mirror: true` 提交给 `POST /jobs`。任务创建后各项上传仍调用现有 `/api/v1/storage/upload` 或 `/api/v1/uploads`，**不允许绕过原有权限和文件修订检查**。
