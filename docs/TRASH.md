# 第十阶段：回收站和文件生命周期

- `POST /api/v1/trash`，请求 `{ "target_type":"file|folder", "target_id":"UUID" }` 将文件或整个文件夹树软删除。
- `GET /api/v1/trash?space_id=UUID` 列举当前空间的回收站条目。
- `POST /api/v1/trash/:id/restore`，请求 `{}` 按原路径恢复；`{"target_folder_id":null}` 恢复到空间根目录。
- `DELETE /api/v1/trash/:id/purge` 永久清理，要求空间管理员或超级管理员权限。
- Cron 每日批量扫描到期条目，合并原先未完成分片清理。

软删除不释放 R2 空间。目录树连同子文件标记为已删除，文件夹可整体恢复。删除时撤销与文件和目录直接关联的分享；恢复不重新启用这些分享。永久清理先移除公开发布副本，再删除 D1 文件记录。私有 R2 对象仅在无其他文件记录引用时删除。

## 已知风险与边界

这是供本地验证的阶段性实现：D1 与 R2 不能参与同一事务，中断清理可能产生部分状态，依靠重复清理重试。跨目录复原遇到已存在同名路径会返回 409；请指定其他恢复目标。完整的幂等事务日志、清理任务状态机、大量目录分批执行与 CDN 缓存清除留待第十一、十二阶段。每次 Cron 批量最多处理 10 条回收站记录，大型目录可能消耗过多 D1 行操作；生产前必须增加队列化清理和性能测试。

### 安全注意

永久公开直链撤销后无法保证已缓存副本立即失效。删除受保护文件时还应阻断浏览器此前发起的正在进行的请求；此机制无法撤回已经下载的内容。

删除时会尝试移除相关公开 R2 副本并停用发布记录；如果对象删除失败，删除流程停止。即使删除成功，CDN 或浏览器中的既有缓存仍可能暂时存在，正式环境应另外配置 Cloudflare 缓存清理机制。
