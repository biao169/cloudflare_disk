# RC14.12 — 个人空间文件夹内文件不显示的修复

## 问题和根因

用户进入 `/personal` 后，可以看到文件夹，但进入文件夹时，即使 `/files` 已经可以浏览其中的文件，页面仍只显示文件夹。

`GET /api/v1/spaces/{spaceId}/contents?parent_id={folderId}` 已正确返回 `{ folders, files, has_more }`。原 `public/js/modules/spaces.js` 只遍历 `folders`，忽略了 `files`；空目录提示也只检查 `folders.length`，因此目录中仅有文件时会误判为空。

## 修复内容

- `/personal` 和 `/spaces` 同时展示 `folders` 与 `files`，文件名使用安全的 `textContent`，不解析文件名 HTML。
- 文件行显示类型、文件大小、按浏览器时区转换的更新时间；支持预览（图片、PDF、受支持视频）及浏览器原生下载。
- 支持文件夹点击/双击打开，显示可点击的目录面包屑，直接返回根目录或上级目录。
- 每页向已有 API 请求 50 个位置的目录数据，若有后续数据，展示“加载更多文件和文件夹”；每页分别合并文件夹和文件结果，无需一次加载全部目录。
- 只有在当前目录确实没有可见文件夹与文件、并且没有后续页时才显示“当前目录暂无文件或文件夹”。
- 目录切换时丢弃过期响应，防止慢请求覆盖新目录。
- 原有个人空间权限、共享空间 ACL、R2 文件和下载 API 都保持不变。

## 升级

基于 RC14.12 OneDrive Settings UI Full 版源码：

1. 备份当前源码。将增量包按原相对路径覆盖到项目根目录，或使用完整包。
2. 执行 `npm run build`。
3. 执行 `npm run deploy`，确保部署至已有 Worker 并保留原 `wrangler.jsonc` 的账号资源绑定。
4. 登录网站，分别进入 `/personal` 和 `/files`，打开相同的个人空间文件夹，确认文件列表一致。
5. 测试只含文件、无子文件夹的目录；再测试超过 50 个文件时的“加载更多”、多级目录返回、下载和预览。

**无需新的 D1 SQL 迁移、R2 数据转换或新增 Secret**。本次没有改动 Worker API 和数据库结构。

## 本地验证与范围

新增 `tests/personal-folder-contents.test.js`：真实 SQLite/D1 模拟环境下检验目录返回、个人空间 UI 渲染、跨页加载、面包屑导航和非本人访问被拒绝。当前仅完成本地测试，尚未在使用真实登录会话的生产网站上验证。

> 注意：目录 API 仅列出 `status=ready` 且未删除的文件；上传中、回收站或没有权限的文件仍不会显示。
